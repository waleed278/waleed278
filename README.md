## Engineering Workflow

I structure portfolio projects around the same habits used in real software teams:

```text
Issue
  ↓
Focused branch
  ↓
Small commits
  ↓
Pull request
  ↓
CI / verification
  ↓
Reviewable merge
  ↓
Changelog / release planning
```

Current emphasis:

- typed API contracts and clear service boundaries
- deterministic tests around external services
- CI quality gates
- reproducible local environments
- documented architecture and tradeoffs
- explicit distinction between implemented capabilities and roadmap items
- measurable evaluation for AI/RAG behavior
